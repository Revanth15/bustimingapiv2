# BusSing API Endpoint Reference

This document describes the FastAPI endpoints exposed by `main.py` and the routers in `routers/`.

Base URL depends on environment:

- Local development: `http://localhost:8000`
- Production: use the deployed Fly.io app URL

Unless stated otherwise, responses are JSON and errors use FastAPI's default shape:

```json
{
  "detail": "Error message"
}
```

Some read endpoints are cached through disk blob cache. Cache TTLs are configured in `routers/cache.py`.

## Health and Diagnostics

### `GET /`

Purpose: simple root endpoint.

Query params: none.

Response:

```json
{
  "message": "Hello World"
}
```

### `GET /health`

Purpose: health check endpoint for uptime checks.

Query params: none.

Response:

```json
{
  "status": "API is running"
}
```

### `HEAD /health`

Purpose: lightweight health check without a JSON response body.

Response body: empty.

### `GET /memory`

Purpose: returns memory usage for the running API process.

Query params: none.

Response:

```json
{
  "rss_mb": 123.45,
  "vms_mb": 678.9
}
```

Fields:

- `rss_mb`: resident memory currently used by the process.
- `vms_mb`: virtual memory size.

## Bus Arrival and Bus Stop Endpoints

### `GET /bustiming`

Purpose: returns live arrival timings for selected bus services at a bus stop using LTA's `BusArrival` API.

Query params:

| Name | Type | Required | Description |
| --- | --- | --- | --- |
| `busstopcode` | string | yes | 5-digit bus stop code. Validated with `^\d{5}$`. |
| `busservicenos` | string | yes | Comma-separated services, for example `14,196`. Use `all` to return all services at the stop. |
| `userID` | string | no | Optional user identifier. Currently only accepted, not used in processing. |

Response headers:

- `Content-Type: application/json`
- `Vary: Accept-Encoding`
- `Content-Encoding: gzip` may be returned when the client sends `Accept-Encoding: gzip` and compression is smaller.

Response:

```json
[
  {
    "serviceNo": "14",
    "serviceDetails": [
      {
        "busArrivalTime": 2,
        "busLoad": "SEA",
        "busFeature": "WAB",
        "busType": "DD",
        "busMonitored": 1,
        "busLongitude": "103.12345",
        "busLatitude": "1.23456"
      }
    ]
  }
]
```

Notes:

- `serviceDetails` always contains up to 3 entries representing `NextBus`, `NextBus2`, and `NextBus3`.
- `busArrivalTime` is minutes from current Singapore time.
- Missing/invalid arrivals use `busArrivalTime: -100`, `busLoad: "-"`, `busFeature: "-"`, `busType: "-"`, coordinates `"-"`, and `busMonitored: 0`.
- Services are sorted naturally, for example `2`, `14`, `14A`, `196`.

Common errors:

- `400`: no bus services specified.
- `422`: invalid or missing query params.
- `500`: service unavailable due to unexpected processing error.
- `503`: LTA API request failed.

### `GET /getallbusstops`

Purpose: returns all bus stops stored in Supabase.

Query params: none.

Cache: disk blob cache, default TTL 2 days.

Response:

```json
{
  "busStops": [
    {
      "id": "01012",
      "description": "Hotel Grand Pacific",
      "latitude": 1.29684825487647,
      "longitude": 103.85253591654006,
      "road_name": "Victoria St",
      "bus_services": "2,12,33,130"
    }
  ]
}
```

Empty response:

```json
{
  "message": "No records available"
}
```

### `GET /extractBusStops`

Purpose: administrative data refresh endpoint. Fetches bus stops from LTA, combines them with `busStopAvailableServices` from the `jsons` table, and upserts changed bus stops into Supabase `bus_stops`.

Prerequisite: `busStopAvailableServices` must already exist in the `jsons` table, typically generated by `GET /extractBusRoutesData`.

Query params: none.

Response:

```json
{
  "message": "Bus stops processed successfully",
  "new": 12,
  "updated": 4
}
```

Common errors:

- `500`: missing `busStopAvailableServices`, failed Supabase upsert, or unexpected processing error.
- `503`: LTA API request failed.

## Bus Route and Bus Service Endpoints

### `GET /extractBusRoutesData`

Purpose: administrative data refresh endpoint. Fetches LTA bus route data, formats it by service, builds the stop-to-services lookup, and upserts the stop-to-services lookup into Supabase `jsons` with id `busStopAvailableServices`.

Query params: none.

Response:

```json
{
  "message": [
    {
      "serviceNo": "14",
      "routes": [
        {
          "direction": "1",
          "busStopIDs": ["84009", "84019"],
          "polyline": ""
        }
      ]
    }
  ]
}
```

Notes:

- The current code prepares `bus_route` rows but does not upsert them because the Supabase upsert block is commented out.
- It does upsert `busStopAvailableServices` into the `jsons` table.

### `GET /extractBusRoutesRawData`

Purpose: administrative data refresh endpoint. Fetches raw LTA bus route data, restructures it by bus stop, and upserts rows into Supabase `bus_route_raw`.

Query params: none.

Response:

```json
{
  "message": "Extracted and stored successfully"
}
```

Stored row shape in `json_value`:

```json
{
  "bus_stop_code": "01012",
  "services": {
    "14": {
      "service_no": "14",
      "operator": "SBST",
      "directions": {
        "1": {
          "direction": 1,
          "stop_sequence": 5,
          "distance": 3.2,
          "schedules": {
            "weekday": {
              "first_bus": "0530",
              "last_bus": "2330"
            },
            "saturday": {
              "first_bus": "0530",
              "last_bus": "2330"
            },
            "sunday": {
              "first_bus": "0600",
              "last_bus": "2330"
            }
          }
        }
      }
    }
  }
}
```

### `GET /getBusStopAvailableBussesData`

Purpose: returns the stop-to-services lookup stored in Supabase `jsons` with id `busStopAvailableServices`.

### `GET /getBusServicesData`

Purpose: returns bus service metadata. Reads from Supabase `jsons` id `busServices` unless `overwrite=true` is supplied or no cached data exists.

Query params:

| Name | Type | Required | Default | Description |
| --- | --- | --- | --- | --- |
| `overwrite` | boolean | no | `false` | When `true`, fetches latest LTA bus services and upserts them to Supabase. |

Response:

```json
[
  {
    "serviceNo": "14",
    "operator": "SBST",
    "direction": "1",
    "category": "TRUNK",
    "originCode": "84009",
    "destinationCode": "10009",
    "amPeakFreq": "06-08",
    "amOffpeakFreq": "08-10",
    "pmPeakFreq": "06-08",
    "pmOffpeakFreq": "09-12",
    "loopDesc": ""
  }
]
```

Response headers when served from Supabase cache:

- `Cache-Control: public, s-maxage=86400, stale-while-revalidate=86400`

### `POST /bus-routes/polylines`

Purpose: builds bus route records for selected service numbers and attaches polyline data from `https://data.busrouter.sg/v1/routes.min.geojson`.

Request body:

```json
{
  "serviceNumbers": ["14", "196"]
}
```

Response:

```json
{
  "bus_routes": [
    {
      "serviceNo": "14",
      "routes": [
        {
          "direction": "1",
          "busStopIDs": ["84009", "84019"],
          "polyline": "[[1.23,103.45],[1.24,103.46]]"
        }
      ]
    }
  ]
}
```

Notes:

- `polyline` is a JSON string containing an array of `[latitude, longitude]` pairs.
- If no GeoJSON coordinates match a route direction, `polyline` is an empty string.

Common errors:

- `502`: failed to fetch the GeoJSON source.
- `503`: LTA API request failed.

### `POST /bulkUpdateBusRoutes`

Purpose: administrative endpoint. Upserts many bus route objects into Supabase `bus_route` by `service_no`.

Request body:

```json
{
  "bus_routes": [
    {
      "serviceNo": "14",
      "routes": [
        {
          "direction": "1",
          "busStopIDs": ["84009", "84019"],
          "polyline": "[[1.23,103.45],[1.24,103.46]]"
        }
      ]
    }
  ]
}
```

Response:

```json
{
  "message": "Bulk update successful"
}
```

Common errors:

- `500`: Supabase upsert failed.
- `422`: invalid request body.

### `DELETE /bus-routes`

Purpose: administrative endpoint. Deletes bus routes from Supabase `bus_route` by service number.

Expected request body:

```json
{
  "serviceNumbers": ["14", "196"]
}
```

Response:

```json
{
  "deleted": 2,
  "serviceNumbers": ["14", "196"]
}
```

### `POST /cache/purge`

Purpose: administrative endpoint. Clears disk blob cache.

Query params:

| Name | Type | Required | Description |
| --- | --- | --- | --- |
| `key` | string | no | Cache key to delete. If omitted, clears all cached blobs. |

Response when `key` is supplied:

```json
{
  "message": "Cache key '/getallbusstops' purged",
  "deleted": true
}
```

Response when `key` is omitted:

```json
{
  "message": "All cache purged",
  "deleted": 6
}
```

## Rail and MRT Endpoints

### `GET /mrt_crowd_density`

Purpose: returns real-time MRT platform crowd density for one or more LTA train lines.

Query params:

| Name | Type | Required | Description |
| --- | --- | --- | --- |
| `mrt_lines` | array of strings | yes | Repeat the query param for multiple lines, for example `/mrt_crowd_density?mrt_lines=EWL&mrt_lines=NSL`. |

Response:

```json
{
  "lines": {
    "EWL": {
      "StartTime": "2026-05-23T12:00:00",
      "EndTime": "2026-05-23T12:10:00",
      "Stations": [
        {
          "Station": "EW1",
          "CrowdLevel": "l"

```

If LTA returns no data for a line:

```json
{
  "StartTime": "",
  "EndTime": "",
  "Stations": []

```

Common errors:

- `422`: missing `mrt_lines`.
- `503`: LTA API request failed.

## Directions Endpoints

### `POST /transit_route`

Purpose: returns simplified public transport route plans from OneMap. The endpoint authenticates with OneMap, fetches route plans, decodes encoded leg geometry into coordinate arrays, and strips the response down to app-friendly itinerary fields.

Request body:

```json
{
  "start_lat": 1.3001,
  "start_lon": 103.8001,
  "end_lat": 1.3101,
  "end_lon": 103.8101,
  "date": "05-23-2026",
  "time": "12:30:00"
}
```

Body fields:

| Name | Type | Required | Description |
| --- | --- | --- | --- |
| `start_lat` | number | yes | Start latitude. |
| `start_lon` | number | yes | Start longitude. |
| `end_lat` | number | yes | End latitude. |
| `end_lon` | number | yes | End longitude. |
| `date` | string | no | Forwarded to OneMap as `date`. Format should match OneMap routing API expectations. |
| `time` | string | no | Forwarded to OneMap as `time`. Format should match OneMap routing API expectations. |

Response:

```json
{
  "from": {
    "name": "Origin",
    "lat": 1.3001,
    "lon": 103.8001
  },
  "to": {
    "name": "Destination",
    "lat": 1.3101,
    "lon": 103.8101
  },
  "itineraries": [
    {
      "duration": 1800,
      "transfers": 1,
      "fare": "1.90",
      "walk_distance": 450.5,
      "start_time": 1779510600000,
      "end_time": 1779512400000,
      "legs": [
        {
          "mode": "BUS",
          "distance": 3500.2,
          "start_name": "Start Stop",
          "start_code": "01012",
          "end_name": "End Stop",
          "end_code": "02011",
          "route_id": "14",
          "coordinates": [[1.3001, 103.8001]],
          "duration": 900,
          "intermediate_stops": [
            {
              "name": "Middle Stop",
              "arrival": 1779511000000,
              "departure": 1779511060000,
              "lat": 1.305,
              "lon": 103.805,
              "stopCode": "01022"
            }
          ]
        }
      ]
    }
  ]
}
```

Common errors:

- `401`: OneMap authentication failed.
- OneMap non-200 statuses are forwarded with `detail: "OneMap API error: ..."`.
- `422`: invalid request body.

### `POST /transit_route_full`

Purpose: returns the full OneMap public transport routing API response without simplifying or decoding itineraries.

Request body: same as `POST /transit_route`.

Response shape: full OneMap routing response.

Note: this endpoint uses `ONEMAP_API_TOKEN` directly instead of the email/password token flow used by `POST /transit_route`.

## Device Token and Feedback Endpoints

### `POST /registerDeviceToken`

Purpose: stores or updates a device token in Supabase `devices`.

Request body:

```json
{
  "token": "apns-device-token",
  "device_type": "iOS",
  "device_model": "iPhone16,1",
  "system_version": "18.0",
  "app_version": "1.2.3",
  "push_to_start_token": "optional-live-activity-token"
}
```

Body fields:

| Name | Type | Required | Description |
| --- | --- | --- | --- |
| `token` | string | yes | Device token. Stored as `devices.id`. |
| `device_type` | string | yes | Device platform/type. |
| `device_model` | string | yes | Device model identifier. |
| `system_version` | string | yes | OS/system version. |
| `app_version` | string | yes | App version. |
| `push_to_start_token` | string or null | no | Optional iOS Live Activity push-to-start token. |

Response:

```json
{
  "message": "Device token registered successfully"
}
```

### `POST /deleteDeviceToken`

Purpose: deletes a device token from Supabase `devices`.

Request body: same model as `POST /registerDeviceToken`.

Minimum body still needs all required `DeviceToken` fields because the endpoint uses the same Pydantic model.

Response:

```json
{
  "message": "Device token deleted successfully"
}
```

### `POST /submitFeedback`

Purpose: stores user feedback in Supabase `feedback`.

Request body:

```json
{
  "device_token": "apns-device-token",
  "message": "The app is missing stop 01012.",
  "app_version": "1.2.3"
}
```

Response:

```json
{
  "message": "Feedback submitted successfully"
}
```

Common errors:

- `500`: failed to insert feedback.
- `422`: invalid request body.

## Administrative Refresh Flow

The README's full refresh order is:

1. `GET /extractBusRoutesData`
2. `GET /getBusServicesData?overwrite=true`
3. `GET /extractBusStops`
4. `GET /extractBusRoutesRawData`
5. Run `scripts/find_difference_route_data.py`
6. `POST /bus-routes/polylines` with new service numbers from script output `c`
7. `POST /bulkUpdateBusRoutes` with the `bus_routes` response from step 6
8. `DELETE /bus-routes` with obsolete service numbers from script output `d`

For rail map data, run:

1. `GET /extractRailMapData`
